# 三件套骨架

> **这是常见骨架，不是必须照抄的固定模板。**
> 如果实际素材指向另一个结构，就按实际的来。产出物是为内容服务的，不是反过来。
> 一份完整示范见 `../examples/EX-01-demand-change.md`。

---

## 通用原则

1. **第一屏必须有结论**。任何一份文档，开头一屏就要能看到：这是什么、给谁用、一句话结论。
2. **事实与推断分标**。所有归纳性内容注明来源；受访者纠偏过的，以他为准。
3. **不许补数字**。素材里没有的时长、人数、满意度分数，一律写成「待确认」或「建议值」。
4. **用具体动作代替抽象名词**。写"跟他确认三件事"，不要写"加强沟通"。

---

## ① 操作手册 + 行为复制检查单

**给谁**：要接手做这件事的人，假设他零经验。
**成功标准**：照单执行，能达到基础质量。

```
封面信息表（适用对象 / 使用目标 / 阅读方式 / 案例参照）

一、行为复制检查单
   （按阶段分组，每组 5 条左右，全部是动作，可打勾）
   建议把这个做成可单独打印的一页

二、方法总览
   （一张表说清整个方法分几段、每段解决什么失败模式）

三、操作工具 × N
   每个工具：适用时机 / 具体话术或步骤 / 红线提示
```

**检查单的写法要求**：
- 每条都是**一个动作 + 一个完成标准**，不是原则。
- ✅ "议题细到某个具体环节，而不是'提升某项能力'"
- ❌ "要注重实效"

---

## ② 案例总结

**给谁**：新人，想理解"这件事当时是怎么发生的"。
**写法**：叙事体，有场景、有转折、有判断。不要写成 PPT 提纲。

```
一、起点（原始需求是什么样的，通常是一句模糊的话）
二、为什么不能照字面做（反面锚点）
三、完整操作全貌（表格：阶段 / 做了什么 / 当时的考虑）
四、三个最关键的动作（每个都讲清「为什么」而不只是「做什么」）
五、关于「人」的细节（怎么分组、怎么处理沉默/抵触）
六、最后的成果与验证（分层列证据）
七、新人可以直接抄走的 N 句话
```

**注意**：这一份的价值在于让人"看见"过程。多放原话，少放结论。

---

## ③ 能力与方法价值提炼 ⚙️（可选项，默认不生成）

**给谁**：需要举证专业能力的人（晋升、答辩、述职）。
**写法**：举证逻辑，**避免形容词堆砌**。每一条能力后面必须跟具体行为证据。

```
一、成果概要（一页看懂：起点/目标/角色/规模/产出/验证/衍生资产）
二、我解决的是哪几个真难题（每条写清"如果处理不好会怎样"）
三、能力解码（表格：能力项 / 具体行为证据 / 稀缺度）
四、最稀缺的两三项能力（展开举证）
五、能力内核（一句话）
六、方法资产化（从个人经验到组织能力：产出清单 + 为什么别人可以复用）
七、价值验证结构（使用者 / 业务侧 / 出资方 / 滞后指标）
八、可迁移方向（标注为前瞻判断，非已达成）
九、待深化方向（自我反思）
```

> 第九条不是走过场。**答辩时这一段最能区分"已达成"与"待验证"，反而加分。**


## Word 排版规范（用户要 Word 时必须遵守）

| 项目 | 要求 |
|---|---|
| 中文字体 | 微软雅黑（用 `w:eastAsia` 设置） |
| 英文/数字 | Times New Roman |
| 一级标题 | 14pt 加粗，深蓝 `#1F4E79` |
| 二级标题 | 12.5pt 加粗，中蓝 `#2E75B6` |
| 正文 | 12pt，黑色 |
| 行距 | 1.2 倍 |
| 表头 | 加粗深蓝 + 底纹 `#DDEBF7` |
| 页面 | A4，左右边距 2.4cm |

**禁止**使用 `doc.add_heading()` 内置样式（字体不受控）。改用普通段落手动控制，表格单元格段落同理。
